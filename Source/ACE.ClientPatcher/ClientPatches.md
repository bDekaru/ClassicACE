# Client patches

Generated by `ACE.ClientPatcher list --markdown`; the data is in `Patches/Data`. Input: the End of Retail acclient.exe (11.6096), MD5 `116d9a66a70b6af449dc3a28d82f2f6d`, SHA-256 `bca95bbebed4b9ed1ff09d0da83144e2fc4208f63ad7ada5cb47c3ca207ccba9`. Entries apply in the order below.

## Code space (`code-space`)

The retail .text is full, so the patches put their code in the zero slack at the end of .text (0x792CE0 to 0x793000) and of .rdata (0x80A600 to 0x80B000). These PE header edits make that slack part of an executable section. Every entry with a cave needs this one.

- **Make the slack at the end of .text and .rdata executable** (CustomDM, Infiltration)
  - `file 0x248`, 2 bytes: .text section header: VirtualSize 0x391CE0 -> 0x392000, so the caves up to 0x793000 lie inside the section
  - `file 0x270`, 2 bytes: .rdata section header: VirtualSize 0x7755E -> 0x78000 (its raw size), so the slack up to 0x80B000 is mapped
  - `file 0x28c`, 4 bytes: .rdata section header: Characteristics 0x40000040 -> 0x60000060 (adds execute)

## Animation break and move-to flags (`animation-break`)

Lets the server drop a creature's queued link animations (MotionFlags.AnimationBreak, bit 0x400 of the first word of a movement packet) and makes MoveToPosition use the new move's flags for its first distance read, as the server does. Both came with the logon version c119.

- **Animation break: a movement packet with MotionFlags 0x400 drops the object's link animations; a Dead motion no longer does it by itself (the server sets the flag on death motions)** (CustomDM)
  - `0x528fcb`, 1 bytes: CMotionInterp::DoInterpretedMotion: the Dead check (cmp edi,40000011h; jne +8 -> jmp +8) always jumps over the call to CPhysicsObj::RemoveLinkAnimations, so a Dead motion no longer drops them by itself
  - `0x5250ef`, 6 bytes: MovementManager::unpack_movement, after reading the first word: jmp to the cave at 0x792D00 (replaces movzx ebp,cx; add eax,2)
  - `0x792d00`, 33 bytes: cave: movzx ebp,cx; add eax,2 (the stolen instructions); test ebp,400h; jz skip; save eax, ecx, edx; ecx = [edi+8] (the physics object); call CPhysicsObj::RemoveLinkAnimations (0x5108F0); restore; jmp back to 0x5250F5

- **Move to position: the packet's movement flags are stored before the first distance read. Retail MoveToPosition measures the distance (GetCurrentDistance, for example the UseSpheres flag) with the previous move's flags and stores the new ones afterwards, so the first position move after a chase could count a waypoint within about 1 m as already reached** (CustomDM)
  - `0x52ae84`, 12 bytes: MoveToManager::MoveToPosition after the position is stored: jmp to the cave at 0x792D40 (replaces mov ecx,esi; mov dword ptr [esi+134h],0)
  - `0x792d40`, 30 bytes: cave: eax = the MovementParameters argument; eax = its flags word (+4); store it in the manager's copy (this+0E0h, the same assignment MoveToPosition makes a few lines later); the stolen mov ecx,esi and mov dword ptr [esi+134h],0; jmp back to 0x52AE90

## Movement (`movement`)

Smoother creature and player movement against the CustomDM server: no back-slide after a sticky, no stuck slide after a collision, a blended stop at arrival, and run speed that changes live. The edits depend on each other in this order: the crossfade rewrites a call inside the arrival cave, the live player speed hooks into the run rate cave, and the blend into the live speed caves. Needs the code-space and animation-break entries.

- **A creature stuck to its target forgets the positions queued before the sticky, so it no longer runs back through them when the sticky ends (back-slides of 2 to 7 m)** (CustomDM)

  - `0x792ce0`, 18 bytes: cave: the same set_target call, then CPhysicsObj::StopInterpolating on the sticky's physics object ([esi+50h]), back to 0x556396

## Spell formula version 4 (`spell-formula-v4`)

SpellFormula::RandomizeForName (0x5BE120) knows versions 1 to 3 and leaves the stored taper ids (63, Red Taper) for any other version, so ClientMagicSystem::CastSpell refuses the cast ("You do not have all of this spell's components") for a player who owns the per-account tapers but no Red Taper, and the spell examine panel shows the wrong tapers. Version 4 takes the scarab from comps[0], the herb from comps[3], the powder from comps[4] and the talisman from comps[6], and fills the taper slots comps[1], comps[2] and comps[5] per account (seeds hash % 0x13D573, 0x4AEFD and 0x96A7F; result % 12 + 63), like the server's RandomizeVersion4. A version 5 would be one more compare in the cave plus another body. Needs the code-space entry.

- **Spell formula version 4: taper slots per account** (CustomDM)
  - `0x5be12d`, 4 bytes: SpellFormula::RandomizeForName: the unknown-version exit (xor eax,eax; retn 8) jumps to the cave
  - `0x80a7c0`, 187 bytes: cave (formula_v4.asm): tests for version 4 (eax = version - 3) and otherwise returns 0 as before; for version 4 builds the components as described above
